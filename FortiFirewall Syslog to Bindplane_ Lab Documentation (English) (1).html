1. Overview and final architecture

The Bindplane agent was installed on Windows and Windows Event Logs were already flowing. The next goal was to send a firewall's logs through the same agent. A Fortinet VM (FortiFirewall v8.0.1) running in VirtualBox was used as the lab firewall.

ComponentDetail
Bindplane agent (collector)Windows VM (VirtualBox, Bridged), IP 192.168.100.42, collector name DESKTOP-QHSR9HE
FirewallFortiFirewall VM (VirtualBox, Bridged, built from the KVM image), IP 192.168.100.44

2. Building the FortiFirewall VM in VirtualBox

2.1 Download the KVM image

VirtualBox has no official Fortinet image, so the KVM image is used and converted. From the Fortinet support site, download the FortiFirewall KVM package (FFW_VM64_KVM-v8.0.1.F-build0245). The zip contains fortios.qcow2; copy it to a local folder such as C:\VMs\FFW_KVM (not OneDrive, to avoid sync problems).

2.2 Convert the qcow2 image to VDI

cd "C:\Program Files\Oracle\VirtualBox"
VBoxManage clonemedium disk "C:\VMs\FFW_KVM\fortios.qcow2" "C:\VMs\FFW_KVM\fortios.vdi" --format VDI

2.3 Create the VM

New VirtualBox VM: Type Linux, Other Linux (64-bit), RAM 2048 MB. On the Hard Disk step, select "Use an Existing Virtual Hard Disk File" and choose fortios.vdi. Creating a new blank disk (the default) will not boot.

Then open the VM settings: Chipset PIIX3, I/O APIC enabled, EFI off, Hard Disk first in the boot order, Paravirtualization KVM. Under Network, use Bridged Adapter with the Intel PRO/1000 MT Desktop adapter type, so the firewall sits on the same LAN as the Bindplane Windows VM.

2.4 First boot

Log in on the console as admin with a blank password. Check the address with get system interface physical. port1 received 192.168.100.44 from the router, which confirms Bridged mode works. The console also warned: "License invalid due to exceeding allowed 1 CPUs and 2048 MB RAM" (see Next steps).

3. Connectivity test

The Windows VM (Bindplane agent) is at 192.168.100.42 on the same subnet. It could ping the firewall with 0% loss. Pinging from the firewall to Windows failed because Windows Firewall blocks incoming ICMP. This does not affect syslog, which uses UDP 514.

4. Syslog forwarding setup

4.1 Syslog on the firewall

config log syslogd setting
set status enable
set server "192.168.100.42"
set mode udp
set port 514
end

4.2 Inbound rule on the Windows VM

New-NetFirewallRule -DisplayName "Bindplane Syslog" -Direction Inbound -Protocol UDP -LocalPort 514 -Action Allow

4.3 Syslog source in the Bindplane configuration

A Syslog source was added to the Windows_logs configuration: Listen IP 0.0.0.0, Port 514, Protocol UDP, Parse Format rfc3164. In the draft, the Syslog line did not reach the destination and the status was "Rollout Pending".

After connecting Syslog to the destination and pressing Start Rollout, both sources feed the destination and data flows (Windows Events 5.1 KB/m, Syslog 1.9 KB/m).

4.4 The agent is listening on port 514

5. Result: logs in Bindplane

Logging in to the firewall GUI (https://192.168.100.44) as admin generated an event log that appeared in Bindplane Live Preview. The log contains logid="0100032001", logdesc="Admin login successful", srcip=192.168.100.13, dstip=192.168.100.44 and user="admin", in FortiOS key=value format.

GUI login and license

The GUI first showed "Authentication failure" (a password issue) and a later login worked. However, the GUI only shows the License page because the VM license is invalid.

Important: syslog events arrived even with the license invalid, but other firewall features may stay limited until it is fixed. The console warned that the VM exceeds the allowed 1 CPU and 2048 MB RAM.

7. Next steps

  1. Fix the license: power off the VM, set CPUs to 1, lower RAM slightly (for example 2000 MB), then check License Status with get system status. If it is still invalid, a valid .lic file or a FortiGate-VM evaluation will be needed.
  2. Add a real destination: Dev_Null discards logs. Add Google Cloud Logging, Splunk, Elastic, Loki or OTLP.
  3. Parse the logs: they are raw key=value text. Add a Bindplane processor (Parse Key Value) so srcip, dstip and action become separate fields.
  4. Generate more logs: enable Log Allowed Traffic → All Sessions on a firewall policy and send traffic through it.
  5. Stable IP: use a DHCP reservation or static IP for firewall port1 so the syslog target does not change after a restart.
